# Правило «не угадывать»

Инструмент: `python3 06_справочные/не_угадывать.py ...`
Дата введения: 28.09.2026

## Зачем

Почти все промахи помощника имели одну природу — **не «не знаю», а «решил, что знаю»**.
Он шёл от памяти и получал правдоподобный неверный результат. Ниже — журнал этих
ошибок и правила, которые их снимают. Правила обязательны, а не рекомендуемы.

---

## Журнал ошибок (доказательная база)

| Ошибка | Что произошло | Чем снимается |
|---|---|---|
| Взял токен GitHub вместо яндексового | `invalid_token` от Метрики | сначала посмотреть, какой токен где лежит |
| `date1=60days ago` | упало на пробеле в URL; Метрика требует конкретную дату | сверить формат параметра |
| `totals` как словарь | это список, упало на `AttributeError` | напечатать форму ответа |
| `display_date` | ключ называется `name` | напечатать форму ответа |
| Перебор `order_by`: DATE, SHOWS, CLICKS | все мимо, надо `TOTAL_SHOWS` | открыть документацию первой |
| Замер пересечений текстов | «совпадают почти все страницы» — это баннер cookie и подвал | вырезать служебный мусор |
| Подсчёт внутренних ссылок по всему HTML | меню и подвал есть на каждой странице | брать только `<main>` |
| Поиск подзаголовка первым `find()` | натыкается на JSON-LD | искать внутри `<main>` |
| `git ls-files` с кириллицей | пути в кавычках, ложная картина «168 файлов исчезло» | `-c core.quotepath=false` |
| Сверка переименованных файлов | взял коммит удаления, где старого пути уже нет | искать первый коммит с непустым выводом |
| Индекс собран до пересборки манифеста | манифест не попал в коммит | правки → манифест → коммит |
| «В поиске 3 страницы» как итог | верно, но неполно: 4 страницы были исключены как `LOW_QUALITY` | искать смежные эндпоинты до вывода |

Общее: **в каждом случае ответ был в спецификации или в сыром ответе, а не в памяти.**

---

## Обязательный чек-лист перед любым утверждением

### 1. Сырой ответ перед выводом

Любой вывод из API — только после того, как напечатан сырой ответ.

```
python3 не_угадывать.py probe --token-env YANDEX_TOKEN "URL"
```

Печатает HTTP-код, заголовки, сырое тело и разбор формы. Пока это не сделано,
писать код под ответ нельзя.

### 2. Форма перед кодом

Перед обращением к полю ответа проверить: объект это или список, и как точно
называются ключи. Типичные ловушки: `totals` — список, а не словарь; у размерности
ключ `name`, а не `display_date`; `data` — список объектов с `dimensions`/`metrics`.

### 3. Имена параметров — из документации, не из памяти

Если API вернул ошибку проверки параметра, документация открывается **первой**,
а не после пятой попытки. Ошибка «Not found enum value» означает, что надо посмотреть
допустимые значения, а не перебирать похожие.

### 4. Служебный мусор вырезать перед сравнением текстов

Любое сравнение, замер пересечений, поиск дублей — только после чистки.

```
python3 не_угадывать.py clean a.html b.html      # два файла + мера пересечения
python3 не_угадывать.py clean a.html --main      # только <main>
python3 не_угадывать.py clean a.html --text      # печать очищенного текста
```

Выбрасываются: `header`, `footer`, `nav`, `aside`, `script`, `style`, `svg`,
`form` и любой элемент с `id`/`class`, похожим на баннер согласия, меню, подвал,
соцкнопки, хлебные крошки.

Замер без этого даёт ложную картину: на главной `zapahstarosti.ru` **45 % сырого
текста — служебный мусор** (1022 слова сырых → 561 после чистки).

### 5. Искать внутри `<main>`, а не первым `find()`

Подзаголовок, описание, ссылки — только в `<main>`. Первый `find()` по всему файлу
натыкается на JSON-LD, `<head>` или меню.

### 6. Показывать вызов, а не только вывод

Если цифра важна, в отчёте должен быть сам вызов: метод, путь, сырой ответ.
Иначе цифру нечем проверить, и она выглядит как утверждение, а не как измерение.

### 7. Кириллица в git — только с отключённым quotepath

```
git -c core.quotepath=false ls-files
```

Иначе пути приходят в кавычках, и сравнение даёт ложное «файлы исчезли».
Надёжнее считать через `Path.rglob('*')` с исключением `.git`.

### 8. Порядок с манифестом

Любая правка файла архива → пересборка манифеста → коммит. Не наоборот.
Правка **после** пересборки роняет проверку; тогда манифест пересобирается заново.

### 9. Неполная находка — не находка

Найдя один эндпоинт или одну цифру, посмотреть смежные, прежде чем делать вывод.
Пример: `summary` дал «3 страницы в поиске». Вывод «сайт почти не попал в поиск» —
неверный. Смежный `/search-urls/events/samples` показал, что 4 страницы **были**
взяты в поиск и **исключены** как `LOW_QUALITY`. Другая причина и другие действия.

## Стоп-условия

Остановиться и проверить, если:

- пишешь код, обращаясь к полю ответа, которого не видел в сыром виде;
- сравниваешь тексты страниц без чистки;
- ищешь подзаголовок или ссылки по всему файлу;
- имя параметра API берёшь из памяти;
- цифра идёт в отчёт без самого вызова;
- правка файла архива сделана после пересборки манифеста;
- вывод сделан по одному эндпоинту, а есть смежные.

---

## Что считается проверенным

Утверждение можно считать проверенным, только если рядом есть: **вызов, сырой
ответ и способ повторения**. Всё остальное — гипотеза, и её надо так и называть.
