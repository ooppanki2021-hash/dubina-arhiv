# Как добавить обновление в существующий архив `dubrava`

**Редакция 19.09.2026. Репозиторий уже существует. Не создавать его заново, не удалять файлы и не очищать историю.**

Автор намеренно сделала архив публичным для передачи помощнику. Публичная ссылка сама по себе даёт чтение. Для актуализации 19.09 автор отдельно поручила помощнику записать обычный коммит в `dubrava`; авторизация в файлы не включается. Изменение видимости не входит в задачу. Ниже — инструкция на случай будущей передачи файлами, а не утверждение о наличии ZIP внутри репозитория.

## Как передавать будущие изменения, если нет прямой записи

- **Полный обновлённый ZIP** — все исходные файлы на своих путях плюс материалы сверки и проверки.
- **ZIP только изменённых и добавленных файлов** — предпочтителен для загрузки поверх существующего репозитория. Отсутствие файла в этом ZIP означает «он не менялся», **не «его нужно удалить»**.
- Git-патч, если прилагается, предназначен для обычного применения к указанному исходному коммиту, не для пересоздания истории.

При подготовке ZIP внутри должны быть сразу папки `01_…`–`06_…`, `README.md` и этот файл — без лишней внешней папки. Папка сайта называется **`03-сайт`**.

## Рекомендуемый способ — компьютер и GitHub в браузере

1. Открыть **https://github.com/ooppanki2021-hash/dubrava** и проверить имя репозитория. **Не `zapahstarosti`, не `apk`.**
2. Посмотреть, не появились ли новые изменения после исходного коммита `006572c7fd9da15bd68a8bc0c626f9b5846af68e`. Если появились — сначала сопоставить их, не перетирать вслепую.
3. Скачать и распаковать пакет **только изменений**. Не загружать ZIP одним файлом вместо его содержимого.
4. На странице существующего репозитория выбрать **Add file → Upload files**. Перетащить папки и корневые файлы с сохранением структуры. Существующие файлы будут обновлены, остальные останутся.
5. Проверить пути перед коммитом. Вложенная страница должна остаться, например, `03-сайт/сайт_текущий/kviz/index.html`, а не корневым `index.html`.
6. Убедиться, что нет удалений и новых посторонних корневых папок. При желании внести это отдельной веткой и pull request, чтобы сначала просмотреть изменения.
7. Сделать обычный коммит, например: **«Актуализация архива 19.09.2026 без удаления файлов»**.
8. После загрузки проверить README, папки упаковки и `05_приложение/`. Не переносить архив в репозиторий рабочего сайта.

Не использовать телефонное приложение GitHub для папок: ранее оно теряло вложенность. Если интерфейс ограничивает число файлов, загружать по папкам, не меняя их пути. Никогда не решать ограничение интерфейса очисткой репозитория.

## Проверка на компьютере

Распаковать полный обновлённый архив или наложить пакет изменений на существующую полную копию. Затем из корня:

```bash
python3 06_справочные/проверить_архив.py
```

Проверка ничего не удаляет, не правит и не отправляет в сеть. Она подтверждает наличие всех 145 исходных путей, контрольные суммы, сохранность новых наработок трекера и соответствие снимка зафиксированной публикации. Она не заменяет испытания продукта или функциональные тесты сайта.

## Почему старая инструкция больше не действует

Репозиторий был создан и восстановлен ранее; инструкция «создать пустой, git init, залить всё» относилась к первичной передаче. Совет удалить папку приложения отменён: автор прямо запретила удаление. Прежняя редакция файла доступна в истории Git. Рецептуры, упаковка и приложение остаются в архиве, видимость управляется только автором.
