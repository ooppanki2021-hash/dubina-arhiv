# Служебное: девять заблокированных скриптов генерации

**Дата:** 03.10.2026 · **Папка:** `04_упаковка/скрипты_генерации/`

## Суть проблемы в одном абзаце

Все девять скриптов генерации макетов лежат внутри `04_упаковка/`, а манифест
целостности объявляет защищённой **всю** папку:

```python
# 06_справочные/манифест_целостности.py
PROTECTED_PREFIXES = ("04_упаковка/", "05_приложение/")
protected = sorted(p for p in new_paths if p.startswith(PROTECTED_PREFIXES))
```

```python
# 06_справочные/проверить_архив.py
require(digest(file_at(relative)) == item['sha256'],
        'Изменён защищённый файл: ' + relative)
```

То есть **любая** правка любого из девяти скриптов роняет самопроверку архива
сообщением «Изменён защищённый файл». При этом скрипты сломаны и в нынешнем виде
не запускаются ни в какой другой среде, кроме рабочей машины автора осенью 2026 года.

Защита здесь работает против цели: она сохраняет нерабочий код неизменным.
Ниже — что именно сломано и как чинить, когда автор снимет защиту.

**Сами скрипты в рамках правки 03.10.2026 не тронуты.** Побайтово как были.

## Три корневые причины

**1. Шрифты Montserrat лежали вне репозитория.**
`/home/user/tools/fonts/Montserrat-` — личная папка рабочей машины. В архиве шрифтов
нет, и взять их неоткуда. Два скрипта (`logo_dubina.py`, `soap_face.py`) без них
не работают вообще.

**2. Папка `uploads/` не попала в архив.**
Три скрипта читают входной файл из `uploads/`. Такого каталога в репозитории нет.
Похоже по имени, что это была папка загрузок конструктора или временная рабочая
директория. Сам рисунок, судя по всему, сохранился — в архиве есть
`04_упаковка/исходники_дизайнера/УСТАРЕЛО_порошок_цветной_40plus_лицо.png` (2,0 МБ),
имя совпадает без префикса папки. **Это гипотеза, не подтверждённый факт:**
побайтово сверить не с чем, исходного `uploads/…` в архиве нет.

**3. Версии файлов разошлись с архивом.**
`add_gel_legal.py` ждёт `_v1` на входе и пишет `_v2`. В архиве лежит `_v3`.
Скрипт писался под промежуточную стадию, которой в архиве уже нет.

## Как чинить — по шагам

### Шаг 0. Снять защиту (решение автора)

Без этого любой из следующих шагов уронит `проверить_архив.py`. Два варианта:

**Вариант А — точечный, рекомендуется.** В `манифест_целостности.py` защитить
в `04_упаковка/` только то, что действительно нельзя менять: готовые макеты и
исходники, но не скрипты.

```python
# было
PROTECTED_PREFIXES = ("04_упаковка/", "05_приложение/")

# стало: макеты и исходники защищены, скрипты — нет
PROTECTED_PREFIXES = ("04_упаковка/финальные_макеты/",
                      "04_упаковка/исходники_дизайнера/",
                      "04_упаковка/ОПИСЬ.md",
                      "05_приложение/")
```

После этого пересобрать манифест: `protected_unchanged_files` станет 31 файл
вместо 40, девять скриптов выйдут из-под защиты. `05_приложение/` остаётся
защищённым целиком — это личный трекер автора, там запреты оправданы.

**Вариант Б — разовый.** Оставить защиту как есть и зафиксировать в манифесте,
что изменение скриптов согласовано. Хуже: согласование придётся повторять
при каждой правке.

### Шаг 1. Шрифты

Приложить Montserrat в архив или перевести скрипты на DejaVu.

Приложить — значит добавить в репозиторий ~500 КБ–1 МБ шрифтов и **проверить
лицензию**: Montserrat распространяется по SIL Open Font License 1.1, встраивание
в репозиторий разрешено, но текст лицензии надо приложить рядом.

Перевести на DejaVu — значит, что макеты получатся **другими**. В
`ЗАПРЕТЫ_И_ГРАНИЦЫ.md` это уже зафиксировано как известное ограничение:
«Узкий гротеск оригинала не повторить — дизайнер заменит шрифт в печатном
исходнике». То есть для печати эти скрипты и так не являются источником истины.

Рекомендация: путь к шрифтам — из переменной окружения, с внятной ошибкой вместо
падения.

```python
# было
F='/home/user/tools/fonts/Montserrat-'

# стало
import os, sys
F = os.environ.get('DUBINA_FONTS', '/home/user/tools/fonts/Montserrat-')
if not Path(F + 'Regular.ttf').is_file():
    sys.exit(f'Не найден шрифт {F}Regular.ttf. Задайте DUBINA_FONTS — '
             'папку, в которой лежат Montserrat-Regular.ttf и Montserrat-Bold.ttf.')
```

### Шаг 2. Папка `uploads/`

Заменить на реальный путь в архиве — но **только после того, как автор подтвердит**,
что `04_упаковка/исходники_дизайнера/УСТАРЕЛО_порошок_цветной_40plus_лицо.png`
и есть тот самый файл, который лежал в `uploads/`. Без подтверждения это угадывание,
а правило «не угадывать» в этом проекте обязательное.

```python
# было
face = Image.open('uploads/УСТАРЕЛО_порошок_цветной_40plus_лицо.png').convert('RGB')

# стало — путь от расположения самого скрипта, с проверкой
HERE = Path(__file__).resolve().parent
SRC_FACE = Path(os.environ.get(
    'DUBINA_FACE', HERE.parent / 'исходники_дизайнера/УСТАРЕЛО_порошок_цветной_40plus_лицо.png'))
if not SRC_FACE.is_file():
    sys.exit(f'Не найден исходник: {SRC_FACE}. Задайте DUBINA_FACE.')
face = Image.open(SRC_FACE).convert('RGB')
```

### Шаг 3. `make_spines_light.py` — убрать `exec`

Сейчас скрипт берёт «движок» из соседнего файла, разрезая его текст по строке
`left=[`:

```python
exec(open('make_spines.py').read().split('left=[')[0])
```

Три проблемы сразу: относительный путь (запуск не из своей папки падает),
чтение без явной кодировки, и `exec` от содержимого файла — приём, на который
справедливо ругается любой анализатор безопасности.

**Правильное решение — вынести движок в общий модуль.** Но `make_spines.py`
тоже защищён, а новых файлов в `04_упаковка/скрипты_генерации/` создавать нельзя:
`числа_readme.py` считает их количество и подставляет в README
(`@scripts@ скриптов`, сейчас 9). Новый файл собьёт это число.

Значит, порядок такой:

1. снять защиту (шаг 0);
2. вынести общие функции `fit()`, `render()` и константы `F`, `FB`, `PW`, `PH`, `BG`
   из `make_spines.py` в новый файл `spines_engine.py`;
3. в обоих скриптах заменить `exec(…)` на `from spines_engine import fit, render, PW, PH, BG`;
4. **одновременно** учесть, что скриптов станет 10: `числа_readme.py` посчитает это
   сам и предложит правку README — её надо применить, а не править число вручную.

Если новый файл создавать не хочется, минимальная правка — оставить `exec`,
но сделать его воспроизводимым:

```python
from pathlib import Path
_engine = Path(__file__).resolve().with_name('make_spines.py').read_text(encoding='utf-8')
exec(compile(_engine.split('left=[')[0], 'make_spines.py[engine]', 'exec'))
```

Это чинит путь и кодировку, но `exec` остаётся. Полноценным решением не является.

### Шаг 4. `/tmp` и тяжёлые зависимости

`build_logo2.py:107` пишет предпросмотр в `/tmp/lp.png`. В песочнице `/tmp`
не переживает смену шага, а в архиве этот файл никому не нужен. Заменить на
`tempfile.gettempdir()` или убрать вовсе — это отладочный артефакт.

`scipy.ndimage` (в `build_logo2.py`) и `cv2` (в `soap_face.py`) — тяжёлые
зависимости. В чистой среде их может не быть, установка OpenCV занимает минуты.
Стоит записать требования рядом со скриптами — но **не** новым файлом в той же
папке (см. шаг 3 про подсчёт скриптов), а в `04_упаковка/ОПИСЬ.md`.

### Шаг 5. Порядок запуска

После правок — штатный порядок архива, нарушать его нельзя:

```bash
python3 06_справочные/числа_readme.py              # показать, что разъехалось
python3 06_справочные/числа_readme.py --применить  # привести README к факту
python3 06_справочные/манифест_целостности.py      # пересобрать манифест ПОСЛЕ правок
python3 06_справочные/проверить_архив.py           # должно сказать «Проверка пройдена»
git add -A && git commit                            # обычный коммит, без force-push
```

Манифест — **последним**. Если собрать его до правок, он запомнит хеши файлов,
которых уже нет, и самопроверка покажет ложное расхождение. Это уже случалось:
описано в комментарии внутри `актуализация_снимка.py` и в сообщении коммита
`6939f21`.

## Что НЕ надо делать

- **Не переписывать макеты.** `УСТАРЕЛО_*` помечены устаревшими намеренно: внутри
  них бренд «ДУБРАВА 40+», в печать нельзя. Актуальны файлы `ДУБИНА_*`. Чинить
  скрипты имеет смысл ровно настолько, насколько нужно для перегенерации
  актуальных макетов, а не для воспроизведения устаревших.
- **Не запускать скрипты «посмотреть, что будет»** до снятия защиты. Они пишут
  PNG рядом с собой — то есть прямо в защищённую папку, и самопроверка упадёт
  уже на результате запуска, а не на правке.
- **Не добавлять файлы в `04_упаковка/скрипты_генерации/`** без одновременной
  правки чисел через `числа_readme.py`.
- **Не считать, что шрифт Montserrat можно взять из интернета молча.**
  Проверить лицензию и приложить её текст.
